# L5 — English track

Written from memory, in my own words, self-corrected across review where wrong.

**Classes, `__init__`, `self`, instance attributes, methods (final, corrected version):**
> Class is like a blueprint, it has methods inside it. `__init__` is a method inside a class, what runs automatically at first when the class is instantiated. Whereas the other methods need to be called individually. `self` goes to every method including `__init__` as the first parameter, it refers to the working instance itself. Instance is an individual copy of a class with real values in it, not placeholders. Instance attributes are data stored on one individual object via `self.name = value`, that's how each instance has it's own independent copy. Methods work like functions, everything same but it's only defined inside a class and the first parameter is always self. Python automatically slots any instance call into it's very own self. Methods can read attributes, run a calculation; it not just only mutate.

**What was wrong in earlier passes (self-corrected during review, not by having it rewritten for me):**
- Blank page had almost nothing usable: `class` was described as "something related to function" (it isn't — a class is a blueprint for a new kind of value, unrelated to function mechanics), and `__init__` was described as "the initialization class of a function... read first when a function is run" — describing function-call mechanics, not construction. `self`, instance attributes, and methods were all blank.
- First English draft repeated the same core error from blank page in a new shape: `__init__` was said to run "automatically at first when a method or function inside the class is called" — this claims calling *any* method (e.g. `paint()`) re-triggers `__init__`, which is false. Corrected to: it runs automatically only at instantiation (`Car("red")`), not on every subsequent method call.
- Second draft overcorrected in the other direction: "`__init__` is the only method inside a class" — read literally, this claims a class can have no methods besides `__init__`, contradicted by my own rebuild, which has `task_one` and `task_two` alongside it. Fixed to: `__init__` is *a* method that runs automatically at instantiation — not the only method a class can contain, and not the only method there is.
- Instance attributes were first described only by where the syntax appears ("the attributes that goes after the dot on self.first_task") rather than what they actually are. Corrected to describe the concept: data stored on one individual object via `self.name = value`, which is the actual mechanism that gives each instance its own independent copy.
- Methods were first left almost undefined ("used to help run the instances... works same as a function... that's it") — vague enough to describe nearly anything. Also, a later draft narrowed methods to only mean mutating an attribute's value, which is too narrow — a method can just as well read an attribute or run a calculation without changing anything. Corrected to state both: methods share the `self`-based instance-access mechanism, and mutating an attribute is one thing they can do, not their definition.
