**Scope, *args/**kwargs, and the mutable-default trap (final, corrected version):**
> There are 3 kinds of scopes. Local scope is when you define a variable inside a function, it ends with the function call and only lives inside the function. Global scope is when you define a variable outside a function, most probably on the top of code file, and use it inside the function. Enclosing scope works as the same like the global scope. Still, it works in a nested function, so if you declare a function inside another function, and if you want to alter the variable of the outer function from the nested function, you use nonlocal keyword, like the global one. You only use those when you want to change the variable inside the function. You don't need to use the keywords if you only want to show or print the variable inside the function, not change it. Any assignment to a name inside the function makes that name local for the entire function, that's why we use those keywords, so that we don't get unboundlocalerror when assigning different value to the key inside the function.
>
> *args are parameters pushed together as an argument, they use a tuple. **kwargs are parameters, that has key value pair, and work as a dict. We declare those at the function definition and pass the arguments at the call site using * and ** where needed. The ordering rule applies to the def line, not the call line.
>
> The mutable-default trap is when you declare an empty list in the function definition, you pass values without a list to the function; then it gets added to the function, not replaces the list. Because Python reads the function definition line only once and stores it in memory; then when we call the function, it uses that memory to add values to the list, when we don't pass a list argument to the function. That's the default mutable trap. If you assign a default integer value instead of an empty list, it will cause no problem because integers have no in-place mutation operations like lists have. So it creates a new object and rebinds the local name, it never touches the assigned value in the function definition when count = count + 1 happens.
