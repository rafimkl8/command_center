☁️ Cross-device sync (iPhone ⇄ Windows) — 2 steps left

✅ Firebase project created and wired into sync.js. Project my-command-center-b4bde. Two things left, then your progress syncs and is backed up off-device.

  1. Publish the security rules. Firebase console → Firestore Database → Rules tab → replace everything with the block below → Publish. Do this first — until you do, sync will fail with a permission error.
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trackers/{code} {
      // "get" instead of "read" is deliberate. "read" also grants "list",
      // which would let anyone enumerate every sync code in the database
      // and read all of it. "get" means you must already know the code.
      allow get:            if code.size() >= 12;
      allow create, update: if code.size() >= 12;
      // "delete" is intentionally not granted - the app never deletes.
    }
  }
}
  1. Link your devices. Open the Recovery Audit or the tracker, tap Connect in the top bar, and leave the box blank to generate a strong code. Write it down, then enter that same code on your other device. Done — real-time sync both ways. ✅
First-link tip: connect on your most up-to-date device first (it uploads), then the second device (it downloads & merges — nothing is lost from either side). After that every tick syncs automatically. This is also your only backup: until it is linked, your audit scores exist in exactly one browser and clearing site data would erase them.
What these rules do and don't protect. The Firebase config in sync.js is a public project identifier, not a secret — Firebase is designed that way, and anyone can read it from any deployed site. Your actual protection is the rules above plus a long code: nobody can list what codes exist, and a 12+ character code is impractical to guess. Anyone who does learn your exact code can read and overwrite that one document, so treat the code like a password and never paste it into a screenshot or a chat. It is study checkboxes, not bank details — but the reasoning here is worth understanding, because it is exactly the kind of question you will be asked in an interview. (Your capstone later gets real authentication instead.)

🌐 Hosting it so your iPhone can open it

To open these on your phone, host them free with GitHub Pages:

  1. On GitHub, open this repo → Settings → Pages.
  2. Under Source, pick Deploy from a branch → branch main → folder /(root) → Save.
  3. After a minute your site is live at https://rafimkl8.github.io/command_center/ — open that on your iPhone and laptop, and bookmark / add to home screen.
iPhone home-screen app: open the link in Safari → tap Share → Add to Home Screen. It opens fullscreen like a real app — no APK or App Store needed.
